# CygnetCI Mobile

Flutter app that polls the CygnetCI API and raises a **critical alarm** (sound +
vibration) when an agent's **CPU / RAM / disk** crosses the thresholds configured in
the web Settings page. **Push-free** — no Firebase/APNs/accounts required.

- **Android:** alarms in the foreground *and* in the background (a foreground service
  keeps polling when the app is closed/locked).
- **iOS:** alarms only while the app is open (iOS does not allow periodic background
  polling without push).

## What's in this repo folder
Only the app source (`lib/`, `pubspec.yaml`, `assets/`). The native `android/` and
`ios/` scaffolding is generated by Flutter — see setup below.

## One-time setup
1. Install the Flutter SDK (`flutter doctor`).
2. Generate native scaffolding. `flutter create` will overwrite `pubspec.yaml`,
   `lib/main.dart` and `README.md` with defaults, so restore ours afterwards (this is a
   git repo, which makes that easy):
   ```
   cd CygnetCI.MobileApp
   git add -A && git commit -m "wip: mobile app source"   # snapshot our files first
   flutter create . --org one.cygnet --project-name cygnetci_mobile --platforms=android,ios
   git checkout -- pubspec.yaml lib README.md              # restore our source; keep new android/ ios/
   flutter pub get
   ```
3. Add an alarm sound at **`assets/alarm.mp3`** (see `assets/README.txt`).
4. Set the API URL: edit `lib/config.dart` → `defaultApiBaseUrl` (or enter it on the
   login screen under "Server URL"). It must be the phone-reachable HTTPS URL of the API.

## Android manifest additions
Add these to `android/app/src/main/AndroidManifest.xml` (inside `<manifest>`, above `<application>`):
```xml
<uses-permission android:name="android.permission.INTERNET"/>
<uses-permission android:name="android.permission.VIBRATE"/>
<uses-permission android:name="android.permission.WAKE_LOCK"/>
<uses-permission android:name="android.permission.POST_NOTIFICATIONS"/>
<uses-permission android:name="android.permission.FOREGROUND_SERVICE"/>
<uses-permission android:name="android.permission.FOREGROUND_SERVICE_DATA_SYNC"/>
<uses-permission android:name="android.permission.USE_FULL_SCREEN_INTENT"/>
```
Also set the foreground-service type on the service that `flutter_background_service`
adds (Android 14+): `android:foregroundServiceType="dataSync"`.
Set `minSdkVersion 23` (or higher) in `android/app/build.gradle`.

## iOS notes
- Requires an **Apple Developer account** only to install on a physical iPhone (Apple's
  rule for any app — unrelated to push).
- Background polling is disabled on iOS by design; alarms fire only while the app is open.

## Run
```
flutter run                 # on a connected device/emulator
flutter build apk --release # Android APK for internal distribution
```

## How it works
- Login → `POST /auth/login`, token stored in secure storage.
- Every 30s (`AppConfig.pollIntervalSeconds`) it calls `GET /settings/alert-thresholds`
  and `GET /monitoring/agents/metrics`, compares each agent's CPU/RAM/disk to the
  thresholds, and if any breach exists raises the alarm until you tap **Acknowledge**
  (local, per-device). Offline agents are skipped.
- Toggle **Background monitoring** on the overview screen (Android) to keep watching
  when the app is closed.
